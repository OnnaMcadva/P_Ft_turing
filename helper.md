### Коротко: ФП vs Императивное программирование

*   **Императивный подход (C, Python, Go):**
    Это инструкция «как делать». Мы постоянно меняем состояние программы.
    *Пример:* У нас есть переменная `x = 5`. Мы пишем `x = x + 1`. Значение в ячейке памяти изменилось. Мы используем циклы `while` и `for`, чтобы бегать по массивам и менять их элементы на месте.
*   **Функциональный подход (OCaml, Haskell):**
    Это описание «что это такое» (как в математике). **Переменные неизменяемы (immutable).**
    *Пример:* Если $x = 5$, то $x$ всегда равен 5. Мы не можем написать $x = x + 1$. Вместо этого мы создаем *новое* значение $y = x + 1$.
    Вместо циклов мы используем **рекурсию** и функции высшего порядка (`map`, `fold`).
    Машина Тьюринга идеально ложится на ФП: у нас есть функция перехода $f(\text{состояние}, \text{символ}) \to (\text{новое состояние}, \text{новый символ}, \text{направление})$. Мы просто применяем эту функцию шаг за шагом, получая *новую* ленту и *новое* состояние, не меняя старые физически в памяти.

### Архитектура проекта (Структура файлов и папок)

Для сборки проектов на OCaml сейчас используется стандартный инструмент **Dune** (система сборки) и **Opam** (менеджер пакетов). Мы настроим проект так, чтобы он соответствовал современным стандартам OCaml, но при этом легко собирался через обычный `Makefile`, как требует задание.

Вот структура, которую мы создадим:

```text
ft_turing/
├── Makefile                 # Главный файл сборки (требуется по заданию)
├── dune-project             # Настройки проекта Dune
├── ft_turing.opam           # Описание пакета для OPAM (зависимости)
├── bin/
│   ├── dune                 # Инструкции сборки для исполняемого файла
│   └── main.ml              # Точка входа (обработка аргументов CLI, запуск)
├── lib/
│   ├── dune                 # Инструкции сборки для библиотеки
│   ├── machine.ml           # Типы данных (состояния, переходы, сама машина)
│   ├── tape.ml              # Математическая модель бесконечной ленты
│   ├── parser.ml            # Парсинг JSON-файла конфигурации
│   └── simulator.ml         # Логика симуляции (шаги, логирование, сложность)
├── machines/                # Папка для наших 5 JSON-машин
│   ├── unary_add.json       # 1. Сложение
│   ├── palindrome.json      # 2. Палиндром
│   ├── 0n1n.json            # 3. Язык 0^n 1^n
│   ├── 02n.json             # 4. Язык 0^(2^n)
│   └── utm.json             # 5. Универсальная Машина Тьюринга
└── test/                    # (Опционально) тесты
```

### Математический концепт: Как сделать бесконечную ленту в ФП?

В императивных языках мы бы создали динамический массив и двигали индекс `i`.
В ФП мы используем красивую структуру данных, которая называется **Zipper (Молния)**.

Представь ленту как три элемента:
1.  **Левая часть ленты:** список символов слева от головки (в обратном порядке, чтобы быстро брать левый элемент).
2.  **Текущий символ:** символ прямо под головкой.
3.  **Правая часть ленты:** список символов справа от головки.

```text
Лента:  [ а, б, в, г, д ]
Головка указывает на "в".

В виде Zipper это:
Левая часть (перевернутая): [ б, а ]
Текущий: в
Правая часть: [ г, д ]
```

*   Если мы идем **RIGHT**: "в" уходит в левый список, а голова берет первый элемент из правого списка ("г").
*   Если списки заканчиваются, мы просто подставляем символ пустоты (`blank`).
*   Все операции происходят за $O(1)$ времени и без изменения памяти! Это чистая математика.

### Шаг 1: Создание структуры папок и пустых файлов

Давай начнем. Создай корневую папку `ft_turing` и внутри нее воссоздай эту структуру. Ты можешь сделать это в терминале следующими командами:

```bash
mkdir -p ft_turing/bin ft_turing/lib ft_turing/machines
cd ft_turing

# Создаем файлы конфигурации сборки
touch Makefile dune-project ft_turing.opam

# Создаем файлы исходного кода
touch bin/dune bin/main.ml
touch lib/dune lib/machine.ml lib/tape.ml lib/parser.ml lib/simulator.ml

# Создаем файлы для JSON-машин
touch machines/unary_add.json machines/palindrome.json machines/0n1n.json machines/02n.json machines/utm.json
```
