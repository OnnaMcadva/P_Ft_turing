## 1. Главное отличие: Императивное vs Функциональное программирование

| Критерий | Императивное (C, Java, Python) | Функциональное (OCaml) |
| :--- | :--- | :--- |
| **Суть** | Инструкция: *Как* нужно сделать (шаг за шагом). | Математика: *Что* это такое (определение функций). |
| **Состояние** | **Изменяемое (Mutable).** Переменные можно перезаписывать: `x = x + 1`. | **Неизменяемое (Immutable).** Переменные — это константы. `x` всегда равен `x`. |
| **Циклы** | `for`, `while`, `do-while`. | **Рекурсия** и функции высшего порядка (`map`, `fold`). |
| **Управление памятью**| Ручное (C) или Garbage Collector (Java, Python). | Автоматический высокоэффективный Garbage Collector. |
| **Ошибки** | Исключения (`try-catch`) или возврат кодов ошибок (`-1`, `NULL`). | Тип данных `Result` (`Ok` / `Error`), проверяемый компилятором. |

## 2. Сравнение синтаксиса: C, Python, Java vs OCaml

### А. Объявление переменных и функций
В OCaml всё объявляется через ключевое слово `let`.ocaml
(* OCaml *)
let x = 5
let add a b = a + b

```c
// C
const int x = 5;
int add(int a, int b) { return a + b; }
```
```python
# Python
x = 5
def add(a, b): return a + b
```

### Б. Условные операторы (If-Else)
В OCaml `if` — это **выражение**, а не инструкция. Оно всегда возвращает значение (как тернарный оператор `? :` в Си).

```ocaml
(* OCaml *)
let status = if score > 50 then "Pass" else "Fail"
```
```java
// Java
String status = (score > 50) ? "Pass" : "Fail";
```

## 3. Ключевые концепции OCaml на примере нашего проекта

### Концепция 1: Pattern Matching (Сопоставление с образцом)
Это "супер-switch", который умеет разбирать структуры данных на части. Компилятор OCaml строго следит, чтобы ты обработал все возможные варианты.

Пример из нашего файла `lib/tape.ml` (сдвиг головки влево):
```ocaml
match tape.left with
| [] -> (* Если список слева пуст *)
    { left = []; current = tape.blank; right = tape.current :: tape.right; blank = tape.blank }
| hd :: tl -> (* Если в списке есть голова (hd) и хвост (tl) *)
    { left = tl; current = hd; right = tape.current :: tape.right; blank = tape.blank }
```
*Аналог на Python:*
```python
if not tape.left:
    # обработка пустого списка
else:
    hd = tape.left[0]
    tl = tape.left[1:]
    # обработка
```

### Концепция 2: Структура данных Zipper (Молния)
Как сделать бесконечную ленту без изменения массива в памяти? Мы используем **Zipper**.
Мы представляем ленту как текущий символ (`current`), список символов слева (`left`, записанный задом наперед) и список справа (`right`).

Когда мы двигаемся **вправо**:
1. Текущий символ уходит в начало списка `left`.
2. Первым символом под головкой становится голова списка `right`.
3. Если список `right` пуст, мы просто подставляем `blank` (символ пустоты).

Это позволяет нам двигаться по бесконечной ленте за $O(1)$ времени без единой мутации памяти!

### Концепция 3: Безопасная обработка ошибок через тип `Result`
В OCaml нет `NullPointerException`. Вместо этого функции, которые могут завершиться ошибкой, возвращают тип `result`:
```ocaml
type ('a, 'b) result = 
  | Ok of 'a
  | Error of 'b
```

В файле `lib/parser.ml` мы используем оператор `let*` (монадический bind):
```ocaml
let* alphabet = to_char_list_res (member "alphabet" json) "alphabet" in
let* blank = to_char_res (member "blank" json) "blank" in
```
Если `to_char_list_res` вернет `Error "сообщение"`, выполнение функции **сразу же прекратится**, и вся функция вернет эту ошибку. Больше никаких падений программы из-за забытых `try-catch`!

### Концепция 4: Хвостовая рекурсия (Tail Recursion)
В ФП нет циклов `while`. Вместо них мы используем рекурсию. Чтобы стек не переполнялся, мы пишем **хвостовую рекурсию** — это когда рекурсивный вызов является абсолютно последним действием в функции.

Пример из `lib/simulator.ml`:
```ocaml
let rec step (state : string) (tape : Tape.t) (steps_count : int) ... =
  (* ... логика ... *)
  step t.to_state new_tape (steps_count + 1) (* Последнее действие — вызов себя *)
```
Компилятор OCaml видит это и превращает рекурсию в обычный плоский цикл на уровне машинного кода. Это работает так же быстро, как `while` в Си, и тратит $O(1)$ оперативной памяти.

## 4. Как читать архитектуру нашего проекта

Когда ты откроешь код, читай его в таком порядке:

1. **`lib/tape.ml`** — здесь описана математика бесконечной ленты (Zipper).
2. **`lib/machine.ml`** — здесь лежат типы данных машины Тьюринга (состояния, переходы) и функции валидации.
3. **`lib/parser.ml`** — парсер JSON. Обрати внимание, как красиво он разбирает вложенные структуры с помощью `let*`.
4. **`lib/simulator.ml`** — бесконечный цикл симуляции. Здесь же считается сложность алгоритма (время — по шагам, память — по разнице между максимальным и минимальным индексами головки).
5. **`bin/main.ml`** — точка входа. Парсит аргументы командной строки, ловит любые ошибки и выводит красивую статистику.
